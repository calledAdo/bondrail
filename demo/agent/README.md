# Bondrail paid agent

`GET /api/oracle` answers the default question "health"; `GET /api/oracle?question=...` supports a single nonempty question up to 1200 characters. Both require payment: unpaid requests return an x402 v2 `PAYMENT-REQUIRED` header, one exact EIP-3009 offer for 10000 atomic USDC units to the configured account. Each offer names the requested canonical resource, including whether the query is present. No model/facilitator call runs for unpaid probes. A validated paid request invokes the configured model (currently openai/gpt-oss-20b on Groq) with a 400 token output bound and 25 second timeout, then settles through the x402 SDK. The answer is released only after successful settlement or independently checked receipt reconciliation.

Runtime payment config is read from durable storage on every request. `GET /api/config` exposes the current recipient/revision; `POST /api/admin/config` requires a server-only32character bearer token and `{revision,payTo}`. Revision CAS rejects lost updates and preserves audit history. All deployed replicas must share Redis REST. `AGENT_INITIAL_PAY_TO` initializes an empty store only; changing it does not rewrite existing config. A Next deployment must use the Node runtime.

Copy `.env.example` to `.env.local` for local Next development. Set `AGENT_PUBLIC_URL` to the externally visible origin used by clients and the frozen observer policy. The manifest lists the canonical `/api/oracle` first and retains `/api/oracle?question=health` because existing immutable policies may commit to either URL. Every listed endpoint must return 402 unpaid and pay the account. Do not remove either URL while a policy covers it.

`demo/scripts/setup-demo.ts` derives the policy endpoint from that manifest, preferring `/api/oracle`. An optional `AGENT_URL="$AGENT_PUBLIC_URL/api/oracle"` must match a listed URL exactly. Before issuing a Watched bond, setup fetches the manifest and unpaid endpoints (including additional same-origin manifest endpoints) and runs `@bondrail/observer/protocol`, the same classifier as CRE and the observer. Only Compliant passes; Unknown or Violation stops issuance and prints the reason. `--skip-preflight` skips endpoint classification only for local tests with chain 31337 and `BONDRAIL_ENV=local`; manifest selection/validation still runs. It is never enabled by default and is rejected on testnet.

The supported testnet USDC address is explicit; for chain 31337 configure a local token implementing EIP-3009 and a compatible facilitator. The local-only contract demo token is not silently presented as a paid x402 integration.

The durable request key includes network, token, payer and authorization nonce. Its first accepted request records the resource/question hash and exact payment payload hash. Concurrent/replayed requests cannot trigger a second model call or a second payment charge. EIP-3009 itself does not cryptographically sign HTTP resource/body; first-use binding at this server cannot add those fields to the token signature.

Payment records normally progress `processing → settlement_pending → complete`. A definitive empty-hash facilitator funding/busy/fee-cap refusal instead stores `settlement_retryable` and returns HTTP 503 with `charged:false`, `retryable:true` and the explicit error (for example `insufficient_gas_funds`). Retry the identical signed request after facilitator recovery: one caller atomically retries settlement with the cached answer, without rerunning the model. A failure with a hash or a timeout stays ambiguous and must not claim no charge. A model failure is retained as `work_failed` with no settlement attempt. A process interruption leaves its last durable state; do not automatically resubmit/replace a payment nonce. Responses with unresolved settlement return202 and instruct the client to reuse the same signed request. The cached answer is withheld until the payment is proven.

If a facilitator times out after broadcast, obtain its transaction hash and call authenticated `POST /api/admin/reconcile` with `{paymentKey,transaction}` and `Authorization: Bearer <AGENT_ADMIN_TOKEN>`. Configure server-only `BONDRAIL_RPC_URLS` (ordered, comma-separated) or `BONDRAIL_RPC_URL`; reconciliation uses the shared paced transport. The server verifies RPC chain, a successful receipt with one additional block, exact token `Transfer(from,to,value)` and `AuthorizationUsed(authorizer,nonce)` logs, the recipient account's matching `Settled(payer,value,nonce)` event, and `authorizationState(payer,nonce)` at the receipt block before marking complete. A direct token transfer cannot pass. Retrying the original signed request then returns the cached answer and `PAYMENT-RESPONSE`. See the [operator command](../../docs/deployments/RUNBOOK.md#recovering-settlement_pending-payments). There is no manual mark-paid endpoint. A crash after model generation but before journaling may leave `processing`; this conservative state requires operator investigation and is never blindly retried.

`GET /api/health` reports configuration/storage readiness; it does not claim model or facilitator credentials were tested. Neither preview text nor readiness constitutes a completed payment. The model credential, facilitator paid flow, deployed shared storage and actual receipt reconciliation require configured live integration validation.

The facilitator pays MON gas separately from the payer's 0.01-USDC price. The October 15 deployment snapshot measured **~0.02849 MON per warm settlement**; with the new estimate margin, budget **~4 MON per 100 warm calls including reserve**, subject to the actual RPC estimate and fees. Monitor the facilitator's `/health`, replenish before its estimated remaining count falls below ten, and configure its optional `FACILITATOR_LOW_BALANCE_WEBHOOK_URL`. An agent 202 is not a measurement of whether gas was spent. See the [gas diagnosis and budget](../../docs/deployments/FACILITATOR-GAS.md).
