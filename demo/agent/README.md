# Slice paid agent

`GET /api/oracle?question=...` supports a single question up to1200characters. Unpaid requests return an x402v2 `PAYMENT-REQUIRED` header, one exact EIP-3009 offer for10000atomic USDC units. No model/facilitator call runs for unpaid probes. A validated paid request invokes Kimi with a400token output bound and25second timeout, then settles through the x402 SDK. The answer is released only after successful settlement or independently checked receipt reconciliation.

Runtime payment config is read from durable storage on every request. `GET /api/config` exposes the current recipient/revision; `POST /api/admin/config` requires a server-only32character bearer token and `{revision,payTo}`. Revision CAS rejects lost updates and preserves audit history. All deployed replicas must share Redis REST. `AGENT_INITIAL_PAY_TO` initializes an empty store only; changing it does not rewrite existing config. A Next deployment must use the Node runtime.

Copy `.env.example` to `.env.local` for local Next development. Set `AGENT_PUBLIC_URL` to the externally visible origin used by clients and the frozen observer policy. The watch URL must include the exact canonical query, for example `/api/oracle?question=health`. The supported testnet USDC address is explicit; for chain31337 configure a local token implementing EIP-3009 and a compatible facilitator. The local-only contract demo token is not silently presented as a paid x402 integration.

The durable request key includes network, token, payer and authorization nonce. Its first accepted request records the resource/question hash and exact payment payload hash. Concurrent/replayed requests cannot trigger a second model call or settlement. EIP-3009 itself does not cryptographically sign HTTP resource/body; first-use binding at this server cannot add those fields to the token signature.

Payment records progress `processing → settlement_pending → complete`. A model failure is retained as `model_failed` with no settlement attempt. A process interruption leaves its last durable state; do not automatically resubmit/replace a payment nonce. Responses with unresolved settlement return202 and instruct the client to reuse the same signed request. The cached answer is withheld until the payment is proven.

If a facilitator times out after broadcast, obtain its transaction hash and call authenticated `POST /api/admin/reconcile` with `{paymentKey,transaction}`. The server verifies RPC chain, successful receipt, confirmation, exact token `Transfer(from,to,value)` and `AuthorizationUsed(authorizer,nonce)` logs before marking complete. Retrying the original signed request then returns the cached answer and `PAYMENT-RESPONSE`. There is no manual mark-paid endpoint. A crash after model generation but before journaling may leave `processing`; this conservative state requires operator investigation and is never blindly retried.

`GET /api/health` reports configuration/storage readiness; it does not claim Kimi or facilitator credentials were tested. Neither preview text nor readiness constitutes a completed payment. The Kimi credential/model, facilitator paid flow, deployed shared storage and actual receipt reconciliation require configured live integration validation.
